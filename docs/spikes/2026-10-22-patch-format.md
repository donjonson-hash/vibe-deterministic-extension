# Спайк: формат ответа LLM для патчей (этап 0)

**Дата:** 2026-10-22 · **Стенд:** [spike/patch-eval/](../../spike/patch-eval/) · **Потрачено:** $3.28 из $20 (Claude $2.74, OpenAI $0.54)

## Вопрос

Как LLM должна возвращать изменение: блоками search/replace в JSON (как сейчас)
или полным файлом, который мы сравниваем сами? Насколько надёжно оба формата
проходят наши детерминированные проверки на разных провайдерах?

## Как мерили

- 20 задач на 10 реальных файлах: 6 TS из этого репозитория, 4 JS из
  deterministic-extensions и code-compare-local (см. `fixtures/PROVENANCE.md`).
  Интенты на русском и английском, правки небольшие, в одном файле.
- Проверки из `main`, без исполнения кода: схема → применение патча
  (уникальный непустой блок) → синтаксис → линт новых нарушений.
  Затем проверка интента (текст или регулярка) и смысловой дифф: изменены ли
  сущности, которых задача не касалась («collateral»).
- До 2 повторов с передачей ошибки модели. Claude — 2 прогона каждой задачи,
  локальные модели — 1. Effort `medium`, fallbacks выключены.
  Claude в формате search/replace — через structured outputs; OpenAI —
  через `response_format: json_object`, без `temperature`/`seed` (см. вывод 6).
- Локальные модели — через нативный Ollama `/api/chat`, `num_ctx` 16384,
  на ноутбуке с RTX 4070 8 ГБ.
- **Clean** = патч прошёл все проверки + интент выполнен + нет collateral.

## Что это значит

1. **У облачных моделей (Claude и OpenAI) оба формата одинаково надёжны, но
   search/replace в 2–2.5 раза дешевле и быстрее.** Модель не переписывает весь
   файл. Дешёвые уровни (Haiku 5.5 — ~$0.0005 за задачу, gpt-6-luna — ~$0.0002)
   на этом наборе не уступают старшим моделям. OpenAI тратит примерно вдвое
   меньше входных токенов на те же задачи (другой токенизатор и нет схемы
   structured outputs в промпте).
2. **Маленькие локальные модели ломаются именно на search/replace.** У Qwen 7B
   11 из 16 сбоев — блок не найден или встречается дважды (`return {`,
   `valid(revision, contextKey);`), ещё 5 — синтаксис. Повторы почти не помогают
   (65% → 70%). Полный файл с той же моделью — 100% / 95% clean. В ту же ловушку
   с неуникальным `valid(revision, contextKey);` (T14) один раз попала и
   gpt-6-luna, но исправилась с первого повтора по нашему сообщению об ошибке.
3. **Полный файл несёт риск непрошеных правок, и ловит его только смысловой
   дифф.** gpt-oss в T19 без запроса переписал `import * as ts from "typescript"`
   в `import ts = require("typescript")`. Синтаксис и линт это пропустили, смысловой
   дифф показал `REMOVED import` + `ADDED statement`. Qwen 7B в T19 добавил
   новую верхнеуровневую сущность.
4. **Ollama нестабилен под нагрузкой:** 2 обрыва соединения (`fetch failed`)
   на 160 локальных запросов. А `/v1` не позволяет задать `num_ctx` — длинный
   файл молча обрежется.
5. **Большие локальные модели на ноутбуке — 1.5–2 минуты на правку.**
   Технически работают, но для потокового вайбкодинга это слишком медленно.
6. **Параметры сэмплинга нельзя слать всем подряд.** gpt-6-luna и gpt-6.1-sol
   отвечают HTTP 400 на `temperature: 0` (поддерживается только значение по
   умолчанию). Claude Sonnet 5.5 и Opus 5.5 тоже отклоняют нестандартный
   сэмплинг. Текущий `DeterministicLLMClient` на `main` всегда шлёт
   `temperature: 0, seed: 42` — на современных моделях он сломается сразу.

## Решение

- **Поддерживаем оба формата в одном конвейере** (общие проверки и дифф).
  Формат — свойство профиля модели, а не настройка пользователя:
  - облачные провайдеры (Anthropic, OpenAI, Gemini, OpenRouter) — **search/replace**,
    у Anthropic — через structured outputs;
  - локальные (Ollama, LM Studio) — **полный файл** по умолчанию;
  - Custom URL — search/replace, с переключателем в настройках.
- **Смысловой дифф становится проверкой, а не только отчётом.** Если изменены
  или удалены сущности, не связанные с интентом (особенно `REMOVED import` /
  экспорт), предложение помечается «требует внимания». Принять можно только
  после явного подтверждения.
- **Haiku 5.5 — модель по умолчанию в пресете Anthropic.** Sonnet и Opus
  доступны на выбор.
- **Адаптер Ollama использует нативный `/api/chat` с явным `num_ctx`** и
  до отправки проверяет, что промпт помещается в контекст с запасом под ответ.
  `prompt_eval_count` для этого не годится: Ollama не считает токены
  закешированного префикса.
- **Полный файл требует восстановления формата файла.** Модель возвращает
  текст с LF и без BOM. Перед сравнением и сохранением конвейер приводит ответ
  к стилю переводов строк исходника (CRLF / CR / LF) и восстанавливает BOM.
  Если в исходнике смешанные переводы строк, полный файл не принимается
  (только search/replace). Иначе нарушается контракт семейства о сохранении
  байтов. Для search/replace блоки ищутся в тексте с нормализованными
  переводами строк, а замена вставляется в стиле исходника. Ни то ни другое
  спайк не измерял (см. ограничения).
- **Профиль модели задаёт и параметры запроса:** формат ответа, допустимые
  параметры сэмплинга, способ получить JSON (structured outputs / `json_object` /
  без JSON-режима). Пресет OpenAI по умолчанию — gpt-6-luna, без `temperature`/`seed`.

## Ограничения

- Задачи небольшие и однофайловые; для Claude это потолок, модели между собой
  этот набор не различает. Сложные многофайловые правки не проверялись.
- N маленький (20–40 на конфигурацию), у локальных моделей 1 прогон.
  Проценты — ориентир, а не статистика.
- Интент проверяется регулярками. Одна ложная ошибка грейдера (T08 у Opus:
  `!(maxRetries >= 1)` вместо `maxRetries < 1`) найдена и исправлена,
  ответы переоценены без новых запросов (`regrade.ts`).
- Синтаксис проверяется через `transpileModule`, без проверки типов.
- **Все фикстуры — UTF-8 с LF и без BOM.** Файлы с CRLF, CR, смешанными
  переводами строк и BOM не проверялись ни в одном формате. Ожидаемые
  проблемы: в полном файле модель вернёт LF, и все строки окажутся
  «изменены», а выгрузка перестанет совпадать с исходными байтами; в
  search/replace блоки с `\n` не найдутся в CRLF-исходнике (`NOT_FOUND`).
  Нужен отдельный набор задач на CRLF/BOM до этапа 2.
- Входные токены локальных моделей занижены: Ollama не учитывает
  закешированный префикс промпта (на повторах).
- Сырые ответы gpt-oss 20B были случайно удалены при уборке после
  смоук-теста OpenAI; модель прогнана повторно на исправленном стенде
  (бесплатно, локально), цифры в таблице — из повторного прогона.
