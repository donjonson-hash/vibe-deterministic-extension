# 0003. Стек этапа 1: TypeScript + esbuild, @babel/parser 8, свой детерминированный дифф
Дата: 2026-10-22 · Статус: принято

## Контекст

Этап 1 ROADMAP — офлайн-оболочка Chrome MV3: Try example → дифф → принять →
Undo → скачать ([ADR-0001](0001-chrome-mv3-llm-adapters.md)). Перед реализацией
нужно выбрать язык исходников, парсер для проверок в браузере и способ показа диффа.

Ограничения:
- стадия прототипа, один разработчик, сроки сжаты; бюджета на сервисы нет;
- правила семейства deterministic-extensions: чистое ядро без DOM, сети, часов
  и случайности; явные лимиты; никаких отсечек по времени; пользовательский
  код не исполняется; воспроизводимая упаковка;
- текущий код (VS Code-прототип и стенд спайка) написан на TypeScript, а
  проверки (`astValidator`, `linterRunner`, `semanticDiff`, `contextManager`,
  ~450 строк) построены на Compiler API пакета `typescript`;
- Code Compare Local собирается esbuild 0.28.2 и использует `@babel/parser`
  8.0.7 и `@codemirror/merge` с патчем при сборке.

Замеры 2026-10-22: бандлы esbuild 0.28.2 (minify, browser ESM); время — в Node
на ноутбуке разработчика. В браузере порядок величин тот же, но там не мерили.

| Пакет | min | gzip | Загрузка модуля | Разбор 213 строк (холодный / тёплый) |
|---|---|---|---|---|
| `typescript` 6.0.3 (`createSourceFile` + `transpileModule`) | 3.58 МБ | 1.02 МБ | ~96 мс | 43 / 6.2 мс |
| `@babel/parser` 8.0.7 + плагин `typescript` | 287 КБ | 71 КБ | ~10–15 мс | 13 / 1.3 мс |
| `@codemirror/merge` 6.12.3 + view/state + lang-javascript | 393 КБ | 133 КБ | — | — |

`typescript` 7.0.2 (2026-07-08) — нативный компилятор: пакет содержит бинарники
под платформы и JSON-RPC API (`unstable/sync`, `unstable/async`), а
`lib/typescript.js` в нём нет. В браузере он не работает. Последняя JS-линия
компилятора — 6.0.x.

## Рассмотренные варианты

**Язык**
1. TypeScript + esbuild (bundle), типы проверяет `tsc --noEmit`.
2. `.mjs` + JSDoc с `checkJs` — ближе к ядру семейства, но сборка всё равно нужна
   для npm-зависимостей, а код и тесты пришлось бы переписать.
3. `.mjs` без сборки, как шаблон семейства: тогда нельзя использовать Babel и
   другие пакеты без вендоринга, и пропадают типы.

**Парсер**
1. Компилятор `typescript` 6.0 в worker — минимум переделок, но 1 МБ gzip и
   тупиковая линия: новый синтаксис TS 7+ он не разберёт.
2. `@babel/parser` 8 + плагин `typescript` — маленький и быстрый, развивается
   вместе с синтаксисом, уже есть в семействе; нужно переписать обходы AST.
3. Lezer (`@lezer/javascript`) — разбор терпимый к ошибкам, строгой диагностики
   нет, для проверок не подходит.

**UI диффа**
1. `@codemirror/merge`: редактор, подсветка, поблочный перенос. Но для
   детерминизма CCL патчит его исходник при сборке
   (`scripts/canonical-merge-plugin.mjs`, SHA-256 пин на 6.12.2): штатный
   MergeView пересчитывает дифф по истории правок.
2. Свой детерминированный построчный дифф в чистом ядре + рендер в DOM через
   `textContent`, только просмотр.

## Решение

1. **TypeScript (strict) + esbuild 0.28.2**, версия закреплена точно, как в CCL.
   Ядро семейства вендорится как есть (`.mjs` + `provenance.json` с ревизией и
   SHA-256) и подключается через собственный `.d.ts`. Модули ядра и конвейера
   не импортируют `chrome.*` и DOM (это требование и для ADR-0002).
2. **`@babel/parser` 8.0.7 с плагином `typescript`**, версия закреплена точно, в
   module worker. Синтаксис — первая ошибка парсера с позицией (`errorRecovery: false`).
   Линт — обход AST (`CallExpression` с `eval`/`Function`, `NewExpression Function`,
   `DebuggerStatement`, `TSAnyKeyword`); блокируются только новые нарушения, как
   сейчас. Канонический текст сущности для смыслового диффа — последовательность
   токенов Babel без комментариев (вместо `ts.createPrinter`). Поведение
   фиксируется тестами, перенесёнными из текущих модулей и стенда спайка.
3. **Свой построчный дифф** в ядре: минимальный дифф по LCS/Myers по
   LF-нормализованному тексту, версия политики `line-myers-v1`, явный лимит
   объёма (лимиты документа ядра). При превышении лимита — явный отказ, а не
   приближённый результат. Отсечек по времени нет. Рендер — unified-вид,
   строки только через `textContent`. Подсветки синтаксиса в MVP нет.

## Последствия

- **Проще:** бандл парсера ~71 КБ gzip вместо ~1 МБ; быстрый старт worker;
  дифф полностью наш и проверяем на детерминизм без патчей чужого кода;
  esbuild позволяет в любой момент выпустить `.mjs` (лёгкий отказ от TS).
- **Сложнее:** переписать ~450 строк AST-логики под Babel и перенести тесты
  (оценка M); сообщения об ошибках синтаксиса для LLM будут другими — спайк
  проводился с TS-валидатором, его результаты нужно перепроверить
  `regrade`-ом после переноса; сборка и проверка воспроизводимости ZIP —
  на нас, по образцу CCL.
- **Пересмотреть, если:**
  - нужна проверка типов (её даёт только компилятор TS, а браузерного API у TS 7
    нет — тогда TS 6 в worker или отказ от проверки в браузере);
  - дойдём до поблочного принятия или правки B — тогда `@codemirror/merge` с
    адаптером из CCL;
  - Babel начнёт отставать от синтаксиса TS, который пишут пользователи.
